# paperbridge dependency pins — GENERATED, do not hand-edit.
#
# WHY THIS FILE EXISTS. `uv tool install <wheel>` RE-RESOLVES from PyPI against
# the wheel's `>=` floors; paperbridge's own uv.lock is not consulted and cannot
# be. Without these pins `bibtexparser>=1.4` resolves to 2.0.0 — which HAS
# wheels, so Gate 3 is satisfied, the build goes GREEN, and every BibTeX feature
# breaks at runtime because 2.x removed the v1 API the code uses. A green build
# is the failure mode here, which is why the pins are not optional.
#
# HOW IT IS USED (Dockerfile, paperbridge block):
#   uv tool install -c <this file> -f sandbox_templates/wheels-host/ <wheel>[extras]
# Constraints keep the WHEEL authoritative about what it needs and this repo
# authoritative about which version it gets. `--with` pins would restate the
# graph by hand and drift; installing these as requirements would install them
# INSTEAD of resolving from the wheel, hiding a dependency a future wheel adds.
#
# NO HASHES, deliberately. `uv tool install` has no `--require-hashes` (measured,
# uv 0.12.5), and two of these pins are satisfied by wheels built on this host
# whose hashes PyPI never published. Content verification for those two lives
# where this repo already does it: their sha256 is recorded in SHA256SUMS beside
# them and checked in the Dockerfile BEFORE the install runs.
#
# REGENERATE at the PUBLISHED source_commit, never the member's HEAD (a member
# ahead of the channel is ordinary, not drift — same rule content_check follows):
#
#   COMMIT=$(awk '$1=="paperbridge.wheel"{print $4}' sandbox_templates/VENDORED.lock)
#   MEMBER=$(awk 'NF && $0 !~ /^[[:space:]]*#/ {print; exit}' .paperbridge-dir.local)
#   d=$(mktemp -d)
#   git -C "$MEMBER" show "${COMMIT}:pyproject.toml" > "$d/pyproject.toml"
#   git -C "$MEMBER" show "${COMMIT}:uv.lock"        > "$d/uv.lock"
#   (cd "$d" && uv export --frozen --all-extras --no-dev \
#        --no-emit-project --no-hashes --no-annotate --no-header \
#        --format requirements-txt)
#
# `--no-emit-project` drops the `-e .` line, which a constraints file must not
# contain. The stamp below is asserted against VENDORED.lock by
# `vendor-tools.sh --check`: re-vendoring without regenerating this file is
# caught there rather than discovered in a running container.
