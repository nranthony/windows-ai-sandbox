# =============================================================================
# Outbound domain allowlist for windows-ai-sandbox
# =============================================================================
# One domain per line. A leading dot (e.g. .github.com) matches all subdomains.
# Comments use `#` at the START of a line. INLINE comments after a domain
# WILL BREAK Squid — `dstdomain` treats the whole line (including `#` and
# any trailing text) as one hostname string. Keep notes on their own lines.
#
# POSTURE: STRICT BY DEFAULT.
#
# The package registries and other install-time hosts are COMMENTED OUT, and the
# sandbox therefore cannot reach them. That is the intended steady state, not a
# temporary lockdown: a slopsquat payload can only run if a registry is
# reachable, so the normal condition is that one is not.
#
# Opening one is a deliberate, bounded act — open, do the step, close again:
#
#     scripts/with-egress.sh <profile> --with npm -- 'cd /workspace/x && npm ci'
#
# That opens the tag, runs exactly one command, and restores the file verbatim,
# flock-serialised and sentinel-tracked. Prefer it over editing this file by
# hand: a hand edit has no automatic close, so a widened allowlist outlives the
# task that needed it.
#
# Three lifecycle tiers, top to bottom:
#   - ALWAYS ON: every profile needs these. Never comment out.
#   - PROJECT-PERSISTENT: the dev/ML stack, pinned to specific subdomains where
#     possible (per audit M3 discipline). Package registries and CDNs live here
#     but are COMMENTED BY DEFAULT — uncomment a block only for a setup stage
#     that genuinely needs sustained access, and re-comment it when the stage is
#     done. (This used to say registries were uncommented by default. They are
#     not, and have not been since fc7c0f0.)
#   - PLANNING-MODE: short-lived installs you want to gate manually. Commented
#     by default. Add blocks here for domains reachable only while you're
#     driving the shell.
#
# Whichever tier: an edit here changes NOTHING until the proxy reloads — and
# `verify` will now tell you if a running proxy has drifted from this file
# (scripts/profile.sh <profile> verify).
#
# APPLYING AN EDIT — an edit here does NOTHING until a proxy reload. Squid parses
# this file into memory at startup, so the file on disk is not what is being
# enforced until you say so.
#   Easiest:  just dashboard  ->  Proxy Allowlist  ->  "Save & Reload Proxies"
#   By hand:  docker restart egress-proxy-<profile>
#             or  docker exec egress-proxy-<profile> squid -k reconfigure
#
#   Both work, and that is a CHANGE (2026-08-03). This file used to warn that
#   `squid -k reconfigure` exits 0 while applying nothing. That was true, and the
#   cause was the mount, not the command: proxy/allowed_domains.txt was
#   bind-mounted as a single FILE, which pins an inode at container start, so any
#   atomic replace on the host — vim, sed -i, every git checkout/merge/pull —
#   left the container reading a deleted copy it could never escape.
#
#   docker-compose.yml now mounts the whole `./proxy` DIRECTORY, so the path
#   resolves on every read and the container always sees current bytes. The
#   silent-no-op mode is gone, and reconfigure is trustworthy again.
#
#   `scripts/profile.sh <profile> verify` checks this and fails loudly if the
#   mount ever regresses to a file. See docs/squid-internals.md.
#
# Blocks are tagged like `[name]` for grep — e.g. `grep "\[claude\]" allowed_domains.txt`.
# To bulk-toggle a block: select its lines and `s/^# //` (uncomment) or
# `s/^/# /` (recomment). Blank lines inside blocks are intentional visual
# chunking — Squid ignores them.
# =============================================================================
