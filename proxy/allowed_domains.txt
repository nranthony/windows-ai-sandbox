# =============================================================================
# Outbound domain allowlist for windows-ai-sandbox
# =============================================================================
# One domain per line. A leading dot (e.g. .github.com) matches all subdomains.
# Comments use `#` at the START of a line. INLINE comments after a domain
# WILL BREAK Squid — `dstdomain` treats the whole line (including `#` and
# any trailing text) as one hostname string. Keep notes on their own lines.
#
# POSTURE: STRICT BY DEFAULT.
#
# The package registries and other install-time hosts are COMMENTED OUT, and the
# sandbox therefore cannot reach them. That is the intended steady state, not a
# temporary lockdown: a slopsquat payload can only run if a registry is
# reachable, so the normal condition is that one is not.
#
# Opening one is a deliberate, bounded act — open, do the step, close again:
#
#     scripts/with-egress.sh <profile> --with npm -- 'cd /workspace/x && npm ci'
#
# That opens the tag, runs exactly one command, and restores the file verbatim,
# flock-serialised and sentinel-tracked. Prefer it over editing this file by
# hand: a hand edit has no automatic close, so a widened allowlist outlives the
# task that needed it.
#
# Three lifecycle tiers, top to bottom:
#   - ALWAYS ON: every profile needs these. Never comment out.
#   - PROJECT-PERSISTENT: the dev/ML stack, pinned to specific subdomains where
#     possible (per audit M3 discipline). Package registries and CDNs live here
#     but are COMMENTED BY DEFAULT — uncomment a block only for a setup stage
#     that genuinely needs sustained access, and re-comment it when the stage is
#     done. (This used to say registries were uncommented by default. They are
#     not, and have not been since fc7c0f0.)
#   - PLANNING-MODE: short-lived installs you want to gate manually. Commented
#     by default. Add blocks here for domains reachable only while you're
#     driving the shell.
#
# Whichever tier: an edit here changes NOTHING until the proxy reloads — and
# `verify` will now tell you if a running proxy has drifted from this file
# (scripts/profile.sh <profile> verify).
#
# APPLYING AN EDIT — an edit here does NOTHING until a proxy reload. Squid parses
# this file into memory at startup, so the file on disk is not what is being
# enforced until you say so.
#   Easiest:  just dashboard  ->  Proxy Allowlist  ->  "Save & Reload Proxies"
#   By hand:  docker restart egress-proxy-<profile>
#             or  docker exec egress-proxy-<profile> squid -k reconfigure
#
#   Both work, and that is a CHANGE (2026-08-03). This file used to warn that
#   `squid -k reconfigure` exits 0 while applying nothing. That was true, and the
#   cause was the mount, not the command: proxy/allowed_domains.txt was
#   bind-mounted as a single FILE, which pins an inode at container start, so any
#   atomic replace on the host — vim, sed -i, every git checkout/merge/pull —
#   left the container reading a deleted copy it could never escape.
#
#   docker-compose.yml now mounts the whole `./proxy` DIRECTORY, so the path
#   resolves on every read and the container always sees current bytes. The
#   silent-no-op mode is gone, and reconfigure is trustworthy again.
#
#   `scripts/profile.sh <profile> verify` checks this and fails loudly if the
#   mount ever regresses to a file. See docs/squid-internals.md.
#
# Blocks are tagged like `[name]` for grep — e.g. `grep "\[claude\]" allowed_domains.txt`.
# To bulk-toggle a block: select its lines and `s/^# //` (uncomment) or
# `s/^/# /` (recomment). Blank lines inside blocks are intentional visual
# chunking — Squid ignores them.
# =============================================================================

# ACCEPTED EXCEPTION — [git] is the one gated block that stays OPEN in the
# committed baseline. Decided 2026-08-18; recorded here because the audit probe
# defers to this note, not the other way round.
#
# The reason it is not tunable: Squid gates on `dstdomain`, and both of these are
# github.com:443 over the same transport —
#     git push                                   (the workflow this exists for)
#     uv pip install git+https://github.com/x/y  (arbitrary code, unvetted)
# There is no allowlist configuration that permits the first and denies the
# second. The choice is binary: github.com reachable and both possible, or
# neither. Opening it is therefore an accepted residual, not an oversight, and
# not something a tighter host list can fix.
#
# What holds the install line instead, since this block does not:
#   1. permissions.deny in sandbox_templates/claude/claude-settings.json denies
#      every installer prefix (pip/uv/npm/pnpm/yarn/bun/poetry/cargo/go), the
#      fetch-and-run siblings (npx, npm/pnpm exec, yarn dlx, bunx), AND
#      git push|clone|fetch|pull, gh, glab, curl, wget — plus the interpreter and
#      wrapper routes (bash -c, python -c, env, xargs, eval) a prefix matcher
#      would otherwise be walked around. The audit asserts the installers and vcs
#      categories are live per profile (settings/required_deny_categories).
#   2. sandbox_templates/claude/hooks/deny-destructive.sh blocks the route no
#      Bash matcher can see: editing package.json / pyproject.toml / Pipfile /
#      requirements*.txt to ADD a dependency name, then resolving it with an
#      allowed build command. It also blocks weakening the min-release-age gate.
# So the agent cannot install from GitHub even with this block open. What CAN is
# a human in an attached shell, and the `Bash(just:*)` / `Bash(make:*)` residual
# already documented in claude-settings.json's _comment.
#
# SSH is not an alternative route and never was: squid.conf allows CONNECT to
# 443 only, sandbox-internal is `internal: true`, and DNS is sinkholed. Every
# git remote in these containers is HTTPS through the proxy.
#
# Of the three hosts below, only github.com is needed to clone/fetch/pull/push.
# api.github.com is the `gh` surface (PRs, issues, and `gh auth login`).
# codeload.github.com serves archive tarballs only — git's wire protocol never
# touches it — so it is pure install-vector and closing it costs nothing unless
# a workspace resolves a dependency from a GitHub tarball or an npm
# `github:user/repo` shorthand. Check that before closing it.

# # THIS BLOCK IS INCOMPLETE BY CONSTRUCTION. huggingface.co only serves the
# # metadata request; the bytes come from a CDN host chosen by the server at
# # request time — an X-Xet-Cas-Url response header under Xet (huggingface_hub
# # constants.py:274), or a 302 to a server-picked CDN without it. Neither host
# # appears in any source file, and requests follows the redirect silently, so a
# # denial presents as "download failed" with no host named. Do NOT guess the

# # TCP_DENIED lines out of Squid's access.log, and add the exact hosts seen —
# # the same procedure the [numerai] block documents for its dynamic S3 buckets.
# # Capture that log live; cache.log is tmpfs and docker logs is blind for squid.
# # Setting HF_HUB_DISABLE_XET=1 forces the classic CDN path and narrows the host
# # set (constants.py:283 -> utils/_runtime.py:159) at a cost in download speed.
# # Pinned hosts only, no parent wildcards — same stance as [git].
# # SECURITY: huggingface.co hosts arbitrary user-uploaded repos, so this is a
# # general fetch capability, not a narrow vendor API. It is also the container
# # an agent runs in. That is why this is gated and not always-on. Weights are
# # executable-adjacent (.ckpt is pickle); nothing in this repo inspects them.
# # us.aws.cdn.hf.co is the CDN host the metadata request redirects to, OBSERVED
# # 2026-08-28 pulling a model into my_comfyui, not guessed: huggingface.co
# # tunnelled clean (4x TCP_TUNNEL/200) while the bytes died on
# # `TCP_DENIED/403 CONNECT us.aws.cdn.hf.co:443`. It is the CLASSIC (non-Xet)
# # path — a Xet-backed repo redirects to a xethub CAS host instead, which has
# # NOT been seen here and is therefore NOT listed. The name is region- and
# # provider-shaped (<region>.<provider>.cdn.hf.co), so a model served from
# # another region will deny under a sibling name: read that denial out of
# # access.log too rather than pre-emptively widening to a parent wildcard.

# # --- fal.ai hosted inference + its MCP endpoint [fal] ---
# # The tag is `fal`, NOT `fal.ai`. with-egress.sh matches section tags with
# # `\[[a-z-]+\]`, so a dot in the tag makes the block unopenable: it would sit
# # here looking gated and silently ignore `--with fal.ai` forever.
# #
# # WHAT THIS OPENS, stated plainly because it is not a read-only API. fal runs
# # arbitrary models on ITS GPUs and hands back generated media, so an open tag
# # here is a compute-and-fetch capability the agent drives on its own. Three
# # consequences: whatever it submits leaves the boundary (prompts, and any
# # image or video passed as INPUT); the media hosts return bytes nothing in
# # this repo inspects; and it is metered against a key, so an unattended loop
# # costs money as well as egress. The key belongs in the environment and never
# # in a URL — Squid logs URLs, so a key in a query string is a leak the agent
# # cannot see (same rule as the webfetch broker).
# #
# # OBSERVED denied 2026-08-29, egress-proxy-fluidmomenta access.log, four
# # TCP_DENIED/403 CONNECTs inside 64ms — a reachability probe, not a working
# # run, so these are hosts the client ATTEMPTS, not yet hosts a completed
# # inference needs:
# #   mcp.fal.ai      the MCP endpoint itself
# #   api.fal.ai      NOT in the hand-written list this block came from; the log
# #                   had it. Evidence beats a list every time.
# #   fal.run         synchronous inference
# #   queue.fal.run   queued inference
# #
# # NOT observed. Named by the operator's agent and included so the first real
# # run does not die three hosts deep, one round trip at a time. If any of them
# # never appears in access.log after a working run, DELETE it rather than leave
# # a line nobody can justify:
# #   rest.alpha.fal.ai   queue status / result polling
# #   .fal.media          generated image + video delivery. WILDCARD, and the
# #                       only one in this block: fal serves media from
# #                       VERSIONED hosts (v3.fal.media today), so a pinned
# #                       entry leaves the next version denying on a URL the
# #                       API itself just handed back. Squid reads a LEADING
# #                       DOT as "this domain and every subdomain" — measured
# #                       against the existing .astral.sh line, whose apex
# #                       tunnels 200 — so this replaces fal.media and
# #                       v3.fal.media both. `*.fal.media` is NOT squid
# #                       dstdomain syntax: it matches literally, matches
# #                       nothing, and reads as present while denying.
# #
# # Pinned hosts everywhere EXCEPT media delivery, and the split is deliberate.
# # The API and MCP hosts are the CONTROL surface — where prompts, inputs and a
# # key go — so they stay exact; `.fal.ai` or `.fal.run` as a parent would hand
# # over every future subdomain fal creates, including any write API. .fal.media
# # is the return path, bytes coming back, and its hostnames version. The audit
# # probe reports it as an INFO wildcard for periodic review. A new host outside
